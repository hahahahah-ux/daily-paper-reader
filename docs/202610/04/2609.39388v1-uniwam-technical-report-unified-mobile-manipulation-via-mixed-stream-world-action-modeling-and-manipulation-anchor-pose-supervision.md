## 摘要
移动操作需要精确导航到可操作姿态，随后进行可靠的物体交互。这两个阶段在动作空间和视觉需求上存在差异，使得统一策略学习变得复杂。此外，收集具有明确可操作姿态监督的多样化真实世界导航数据仍然成本高昂且难以扩展。我们提出 UniWAM，一种统一的混合流世界-动作模型，为导航和操作设置独立的动作编码器与输出头，并共享一个通用主干。该设计支持在独立采样的导航和操作数据上进行联合表征学习。UniWAM 支持任一流的独立推理以及两者的批并行推理。我们进一步引入操作锚点姿态（MAP）监督，用于确定在何处停下以及如何调整朝向以进行操作。一个自动化流水线从大规模 3D 场景构建 MAP-Data，产生超过 150 万条 episode 和 7500 小时。MAP-Data 提供逐帧目标物体边界框和图像平面 MAP 坐标，作为辅助导航监督。结合用于操作而投影的末端执行器轨迹，这些预测目标为从第一人称观测中进行动作学习提供了特定于流的图像平面监督。借助大规模 MAP-Data，UniWAM 在我们的 MAP-Bench 上，位置误差比最强外部基线低 30.1%，朝向误差低 44.0%。在 24 个真实机器人任务中，UniWAM 在 MAP 导航和移动操作上取得领先结果，并具有有竞争力的操作性能。我们已发布代码、数据和基准。

## Abstract
Mobile manipulation requires precise navigation to a manipulation-ready pose followed by reliable object interaction. These two stages differ in action spaces and visual requirements, which complicates unified policy learning. In addition, collecting diverse real-world navigation data with explicit manipulation-ready pose supervision remains costly and difficult to scale. We introduce UniWAM, a unified mixed-stream world-action model with separate action encoders and output heads for navigation and manipulation, sharing a common backbone. This design supports joint representation learning on independently sampled navigation and manipulation data. UniWAM supports independent inference for either stream and batch-parallel inference for both. We further introduce Manipulation Anchor Pose (MAP) supervision for where to stop and how to orient for manipulation. An automated pipeline constructs MAP-Data from large-scale 3D scenes, yielding over 1.5 million episodes and 7,500 hours. MAP-Data provides per-frame target-object bounding boxes and image-plane MAP coordinates as auxiliary navigation supervision. Together with projected end-effector trajectories for manipulation, these prediction targets provide stream-specific image-plane supervision for action learning from egocentric observations. With large-scale MAP-Data, UniWAM outperforms the strongest external baselines on our MAP-Bench by 30.1\% in position error and 44.0\% in heading error. Across 24 real-robot tasks, UniWAM achieves leading results in MAP navigation and mobile manipulation, with competitive manipulation performance. We have released code, data, and benchmark.

## 1. 核心问题与研究动机

### 1.1 背景

移动操作（Mobile Manipulation）要求机器人**先精确导航到可操作姿态，再完成物体交互**。相比单独的导航或固定基座操作，它能支撑更广泛的任务（如跨房间取物、清理桌面），但两个阶段存在本质差异：

- **视觉需求不同**：导航需要前向广角视野（关注远处目标与自由空间）；操作需要局部工作空间的高分辨率视图（常来自下视与腕部相机）。
- **动作空间与控制频率不同**：基座运动缓慢平滑、覆盖长距离；机械臂与夹爪在接触附近变化迅速。

### 1.2 现有方法的两条路线与两大挑战

| 路线 | 做法 | 问题 |
|---|---|---|
| **模块化系统** | 分别训练导航与操作策略，执行时拼接 | 模块间接口会传播误差（handoff errors） |
| **统一模型（VLA/WAM）** | 单一策略端到端学习完整过程 | 共享动作 token 忽略异构观测与动作空间；每个训练样本同时监督两种行为 |

论文指出两个相互关联的挑战：

1. **架构挑战**：共享动作 token（如 π0.5、GR00T）或仅在动作模块内分离（如 ABot-M0.5、MobileWAM）的设计，仍要求每个样本同时监督导航与操作目标。由于移动操作本质上是**顺序性**的（导航时机械臂空闲、操作时基座空闲），联合监督会把大量训练浪费在静止命令上，且无法直接使用更容易采集的**纯导航或纯操作数据**。
2. **数据挑战**：现有统一模型只能从完整移动操作轨迹中**隐式**学习"可操作终端位姿"，因此需要昂贵的大规模移动操作数据。语义导航数据虽易扩展，但只指定目标邻近性，不指定操作所需的终端位姿。缺乏此类数据时，策略可能到达目标附近但停在不合适的位置或朝向，导致后续操作失败。

### 1.3 整体含义

UniWAM 试图同时解决上述两个挑战：用**混合流架构**分离导航与操作的控制流，用**MAP（操作锚点姿态）监督 + 自动生成的大规模 MAP-Data** 显式监督"在哪里停、以什么朝向停"。这使统一策略既能利用纯导航数据、纯操作数据，也能利用完整移动操作数据，并支持单流独立推理与双流批并行推理。

## 2. 方法论

### 2.1 核心思想

UniWAM 将导航与操作建模为**两个独立采样的控制流**，共享视频 DiT（基于 Wan2.2-TI2V-5B）与动作 DiT（30 层 Transformer，隐藏维度 1024；视频 DiT 隐藏维度 3072），通过 Mixture-of-Transformers（MoT）注意力耦合。每个流拥有自己的视觉输入、动作编码器、输出头与可学习 token。

### 2.2 Manipulation Anchor Pose（MAP）定义与生成

**MAP 定义**：对操作目标 $o_i$，其 MAP 为 $m_i = (p_i^{MAP}, \theta_i^{MAP})$，其中 $p_i^{MAP} \in \mathbb{R}^2$ 为基座位置，$\theta_i^{MAP} \in S^1$ 为朝向。MAP 由场景几何定义（而非特定策略），可对 3D 场景中任意目标自动计算。

**计算方式**：VLM 识别目标面向操作的前边缘，取其地面中点 $p_f$ 与指向可通行空间的单位法向 $n_f$，则

$$
p^{MAP} = \text{Ray}(p_f, n_f) \cap \partial \mathcal{F}_{nav}, \quad
\theta^{MAP} = \text{atan2}\big((p_f - p^{MAP})_y, (p_f - p^{MAP})_x\big)
$$

即从目标前边缘沿法向射线与可通行区域边界的交点作为停车位置，朝向使机器人正对目标表面。

### 2.3 MAP-Data 自动构建流水线（三阶段）

| 阶段 | 内容 |
|---|---|
| **S1 大规模物体筛选** | 将 HM3D、HM3D-Semantics、InteriorGS 及内部场景统一表示；经语义有效性、几何与视觉、基座放置可行性、可见性/渲染四道过滤，保留有效目标 |
| **S2 几何标注** | 为每个目标生成 MAP 与可行观测位姿；观测位姿独立采样（距离、方位、相机朝向），仅在基座位于可通行自由空间、满足碰撞与几何约束、且对目标有有效视图时保留 |
| **S3 轨迹与数据合成** | 用单段或多段三次贝塞尔曲线连接观测位姿与 MAP；若直连受阻，用 A* 提供无碰撞走廊引导分段拟合；轨迹需满足导航掩码、朝向、视野、曲率与路径长度约束 |

**同步几何标签**：每步记录第一人称 RGB 观测与平面导航动作；MAP 位置经相机投影得 $u_t^{MAP} = \Pi(T_{c_t \leftarrow w}[x^{MAP}, y^{MAP}, z^{MAP}, 1]^\top)$；目标实例掩码转为图像平面边界框。所有标签与同一时间戳对齐。

**MAP-Data 规模**：超过 **150 万条 episode、7500+ 小时**导航轨迹，含 12K+ 物体、580K+ 观测位姿、15K 轨迹；MAP-Bench 训练集 35K+ episode、133+ 小时。

### 2.4 流接口与动作表示

- **导航动作**：预测相对于动作块起始基座位姿的平面位姿增量 $(\Delta x, \Delta y, \Delta\theta)$，而非速度 $(v, \omega)$。原因是速度标签受保守限速影响呈强双峰分布（近似夹爪开合的二值状态），而位姿增量累积后变为连续平滑目标，更易学习。
- **操作动作**：每臂 10 维（3D 末端位置 + 6D 旋转 + 1D 夹爪），双臂共 20 维；6D 旋转取旋转矩阵前两列，经 Gram–Schmidt 正交化恢复完整矩阵；位置与旋转表达在**当前主相机坐标系**下，使视觉相似的运动在不同本体上数值相似。

### 2.5 混合流批打包与注意力

- 编码后的两类样本沿 batch 维度堆叠：$X_{pack} = \text{Concat}_B(X_{manip}, X_{nav}) \in \mathbb{R}^{(B_{manip}+B_{nav}) \times L \times D}$，两个流**仅通过共享权重交互**，注意力不跨 batch 行。
- 行内注意力：动作 token $a^s_{t,j}$ 可读取当前视觉 token、可学习 token、自身及更早动作，但不读取未来动作；当前观测 token 不能读未来帧；动作 token 不能读未来视频 token。
- **前缀条件异步推理**：动作块前 $P$ 个动作为已提交执行的干净动作，因果掩码让后续动作条件于该干净前缀而不泄漏后续噪声动作信息，保证新块与已执行运动一致。

### 2.6 独立流采样

- 将完整移动操作轨迹按规则切分为导航窗口与操作窗口，并标记每个窗口为 active/idle（受控部分是否运动）。
- 采样概率 $q(d,i) = \frac{\alpha_d}{\sum_{d'}\alpha_{d'}} \cdot \frac{w_{d,i}}{\sum_j w_{d,j}}$，源内归一化使采样质量与数据规模解耦；窗口权重控制导航/操作、active/idle 比例（实验中 idle 窗口分别降至 20% 与 15%）。
- 批内拒绝重复或时间相邻窗口；同一 episode 的窗口起始帧至少间隔 $\delta$ 帧。

### 2.7 图像平面辅助监督

- 将图像平面目标追加到动作向量：$a^s_{t,i} = [a^{s,act}_{t,i}; a^{s,aux}_{t,i}]$，与动作联合去噪。
- **导航辅助目标**：目标边界框 + 投影 MAP 位置（指示目标在哪、基座应停在哪）。
- **操作辅助目标**：两臂末端执行器在主相机视图的投影轨迹 + 可见性标志。
- 末端执行器轨迹生成含三个算法：Algorithm 1（标定主视图末端几何投影）、Algorithm 2（外观门控可见性，用 DINOv2 特征与正负原型余弦相似度打分，经插值、滞回阈值、形态学清理）、Algorithm 3（全数据集并行生成并校验）。

### 2.8 训练目标与实现

- 所有目标用 **flow matching** 训练：$x_\sigma = (1-\sigma)x + \sigma\epsilon$，$v^* = \epsilon - x$；视频与动作噪声水平独立采样，$\sigma = \kappa u / [1+(\kappa-1)u]$，$\kappa=5$。
- 总损失：$\mathcal{L} = \lambda_{vid}\mathcal{L}_{vid} + \sum_{s \in \{nav, manip\}} (\lambda^s_{act}\mathcal{L}^s_{act} + \lambda^s_{aux}\mathcal{L}^s_{aux})$，各项仅在有效位置与特征上平均，样本只贡献自身流的损失。
- 前缀条件训练：位置 $1 \le t \le P$ 替换为干净已提交动作并排除监督，$P$ 以概率 $p_{pre}$ 从 $\{P_{min}, \ldots, P_{max}\}$ 均匀抽取，否则 $P=0$。
- **推理加速**：训练时用 torch.compile 捕获混合流 Transformer 层完整图；推理时分别编译 VAE 编码器、视觉缓存 prefill、缓存动作去噪函数，当前观测只编码一次，逐层视频 KV 在 10 步 Euler 去噪中复用。双流推理延迟从约 220 ms 降至 **<60 ms**（单张 H200）。
