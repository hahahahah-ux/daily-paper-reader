# ABSTRACT 

A key challenge in bringing embodied intelligence into the real world is trans-ferring capabilities from simulation to reality and enabling agents to continu-ally adapt after deployment. End-to-end vision-language-action policies provide strong manipulation capabilities, but their transfer to physical environments typ-ically relies on calibrating simulated visual and dynamical conditions, collecting additional target-domain demonstrations, and optimizing the policy through fur-ther training. Tool-using embodied agents offer flexible task orchestration, yet existing systems primarily emphasize task execution and experience reuse within a given environment, with limited support for transferring procedural knowledge and continuously adapting it across simulation and reality. We propose Robo-Bridge, a framework that treats sim-to-real transfer as the continued adaptation of executable task skills. The agent represents task knowledge as procedures connecting task intent, observations, tool operations, and outcome verification. Interaction feedback is used to generate candidate skill revisions, which are eval-uated before being persisted or rejected. A pretrained vision-language-action pol-icy is exposed as a reusable action tool and enhanced with inference-time guid-ance, enabling fine-grained execution without retraining the underlying policy. RoboBridge grounds transferable skills in task semantics and interaction inter-faces shared across simulation and reality. This representation preserves reusable task structure while allowing environment-dependent operations to be selectively revised through real-world execution feedback. We evaluate the framework on LIBERO-PRO and corresponding physical tasks, studying both skill evolution and post-transfer adaptation. Our framework provides a route from one-shot policy deployment to continual procedural learning across environments. 

# 1 INTRODUCTION 

Reliable sim-to-real transfer requires robotic systems to preserve task performance across differ-ences in visual observations and physical dynamics (Zhao et al., 2020). End-to-end vision-language-action models provide fine-grained manipulation capabilities by mapping visual observations and language instructions to action sequences (Kim et al., 2024; Black et al., 2024). The policy-centered pathway illustrated in Figure 1 includes adapting simulation conditions using real-world experience (Chebotar et al., 2018). For pretrained VLA models, adaptation to new robotic settings commonly involves target-domain demonstrations and policy fine-tuning (Kim et al., 2025). In this formu-lation, task knowledge is largely embedded in model parameters and learned action distributions. This makes it difficult to isolate a reusable task procedure and selectively revise it when execution conditions change, tying procedural adaptation closely to policy optimization.

RoboBridge evolves procedural skills through a feedback-driven execution loop in simulation and transfers them through aligned task semantics and compatible observation and tool interfaces. After deployment, real-world execution feedback drives further skill evolution, refining the transferred procedures for the target environment. Tool-using embodied agents offer a way to make task procedures explicit (Singh et al., 2022; Rana et al., 2023). An agent harness provides the observation and tool interfaces through which the agent organizes subtasks, invokes operations, and verifies their outcomes (Liu et al., 2026a). Successful procedures can then be retained as skills for subsequent execution (Wang et al., 2023; Lu et al., 2026). Feedback-based memory updates and skill refinement extend this reuse across interactions (Shinn et al., 2023; Wang et al., 2026), and recent robotic systems further incorporate repair valida-tion and validation-gated skill updates (Lu et al., 2026; Ding et al., 2026). Sim-to-real deployment requires these mechanisms to govern which parts of a transferred procedure remain applicable and how the others should be refined using target-environment feedback. Meanwhile, task decompo-sition and tool selection still require an underlying capability to execute continuous, fine-grained manipulation (Yu et al., 2023). Recent harnesses address this execution requirement by exposing frozen VLA policies as reusable manipulation primitives (Zhang et al., 2026b). This perspective motivates a framework that combines revisable task knowledge with the manipulation capabilities of pretrained policies. We propose RoboBridge, a self-evolving embodied agent framework for sim-to-real transfer of pro-cedural skills. RoboBridge incorporates a pretrained VLA policy as a reusable action tool within an agent harness. The policy supplies short manipulation segments, while the agent determines how these operations are organized, when they should be invoked, and whether their outcomes satisfy the task. Task knowledge is stored as procedural skills connecting intent, observations, tool opera-tions, and outcome verification. This organization preserves pretrained execution capabilities while exposing task procedures for revision through interaction. As illustrated in Figure 1, skills evolved in simulation are reused in reality through aligned task semantics and interaction interfaces, with action tools instantiated for each environment. Real-world execution feedback then supports contin-ued skill adaptation. Effective transfer requires both reliable revision of the transferred procedures and accurate execution of their local operations. Reliable execution presents a complementary challenge: even a suitable task procedure can fail when a frozen policy produces actions that do not meet the current subtask requirements (Liu et al., 2026b). Prior work has explored adapting pretrained policy behavior during inference through external guid-ance or verification (Wang et al., 2024; Wu et al., 2025; Liu et al., 2026b). RoboBridge therefore augments the policy tool with inference-time guidance. The agent determines whether guidance is needed and configures a reward specification from the subtask objective, execution constraints, and 2observed feedback. This reward steers action generation toward the intended operation while keep-ing the policy parameters fixed. Skill evolution thus adjusts the procedure across episodes, while inference-time guidance adapts action generation within an invocation. Our contributions are summarized as follows: 1. A self-evolving framework for procedural sim-to-real transfer. We integrate pretrained action capabilities with explicit task skills, enabling procedures evolved in simulation to be reused through aligned interaction interfaces and further adapted from real-world feedback. 2. Controlled skill evolution. We develop a feedback-driven process for adding, revising, and deleting procedural knowledge, with validation governing which updates are persisted and which are rejected or rolled back. 3. Adaptive policy-tool orchestration. We enable the agent to determine when to invoke the pretrained policy, when to activate inference-time guidance, and how to configure subtask rewards, supporting context-dependent execution with frozen policy parameters. 

# 2 RELATED WORK 

2.1 END -TO -E ND EMBODIED MODELS 

End-to-end embodied models learn to map visual observations and language instructions directly to robot actions. Early systems such as RT-1 (Brohan et al., 2022) and RT-2 (Brohan et al., 2023) established this paradigm, while later models expanded its scope through embodied multimodal rea-soning, multi-robot datasets, and generalist policies, including PaLM-E (Driess et al., 2023), Open X-Embodiment (O’Neill et al., 2024), Octo (Team et al., 2024), OpenVLA (Kim et al., 2024), and 

π0 (Black et al., 2024). These models improve generalization by increasing the diversity of training tasks, observations, robot embodiments, and demonstrations, but their behavior remains primarily encoded in a fixed policy. To address the gap between simulation and physical deployment, existing approaches increase the diversity of simulated observations (Tobin et al., 2017), perturb simulated dynamics (Peng et al., 2018), or adapt the simulator distribution using informative variations and posterior estimation (Mehta et al., 2020; Muratore et al., 2022). Recent data-centric methods further scale simulated experiences and adaptation data to improve transfer across tasks and robot embodi-ments (Liu et al., 2025), while inference-time steering adjusts a frozen policy during execution (Liu et al., 2026b). These approaches use a single end-to-end policy to map observations and instructions to actions, leaving adaptation coupled to the policy itself. Our framework instead uses an agent to organize reusable skills and invoke action tools, so the transferred procedure can be revised in the target environment without retraining the entire policy. 2.2 EMBODIED AGENTS 

Embodied-agent research introduces explicit reasoning, tool use, and feedback into robotic execu-tion. Early systems grounded language in executable affordances and used environment feedback for closed-loop planning (Ahn et al., 2022; Huang et al., 2022), while program-based approaches synthesized control logic or composed spatial value functions for manipulation (Liang et al., 2023; Huang et al., 2023). Subsequent work explored skill bootstrapping, lifelong skill libraries, and open-vocabulary adaptation through interaction and memory (Zhang et al., 2023; Tziafas & Kasaei, 2024; Zhao et al., 2025). Recent systems have further studied workflow reasoning, self-directed skill ac-quisition, feedback-based repair, and continual adaptation in simulated or physical environments (Lu et al., 2026; Ding et al., 2026; Wang et al., 2026; Nie et al., 2026; Liu et al., 2026a; Lei et al., 2026; Zhang et al., 2026a). These studies show that explicit procedures, persistent memory, and execution feedback can extend embodied reasoning beyond direct policy execution. Their primary focus, however, varies between workflow planning, skill discovery, memory expansion, and runtime self-improvement. Our work focuses on the migration process itself: a skill is treated as a revisable task hypothesis, and feedback from the target environment determines which parts of the transferred procedure should be retained, modified, or removed. 3Environment

# 3 METHOD 

RoboBridge integrates skill-guided execution, inference-time action guidance, and feedback-driven skill evolution into the closed loop illustrated in Figure 2. During task execution, the agent consults the active skill and current observations to select tool operations, then uses task checks and program outputs to guide subsequent decisions. When invoking the pretrained end-to-end action model, the agent can construct a reward function to steer action refinement during denoising while keeping model parameters fixed. Execution logs from the rollout provide evidence for adding, deleting, or replacing skill content. Candidate skills are evaluated through task execution, and validated improvements are retained to guide subsequent rollouts while unsuccessful revisions are rejected. This loop allows execution experience to improve reusable procedures and updated procedures to guide future actions. With aligned task semantics and compatible observation and tool interfaces, skills evolved in the simulator can initialize real-world execution and continue to adapt through physical feedback. 3.1 PROBLEM FORMULATION AND AGENTIC EXECUTION LOOP 

Task Setup and Skill Evolution. We consider language-conditioned manipulation in a source simu-lator, LIBERO-PRO (Zhou et al., 2026), and corresponding real-robot tasks in a target environment. Each task is specified by an instruction ℓ and a completion condition G. The agent maintains an editable skill S that connects observations to tool operations and verification conditions, providing procedural knowledge for task execution. Skill evolution uses interaction feedback to revise this knowledge. In either environment, a task rollout τk informs the validated update process U. Agentic Execution Loop. Each rollout consists of successive interactions between a high-level planner Π and a unified tool interface P. At turn t, the planner receives an observation ot containing the structured scene description, camera observations, robot state, and observation freshness and uncertainty. Together with instruction ℓ, previous execution feedback ft−1, and the active skill Sk,this information determines the next tool invocation:

The interface provides deterministic manipulation primitives, including gripper and pose controls, policy-based action tools, and task termination. Each turn contains at most one physical operation. Once the operation completes or reports a failure, the updated observation and feedback return to the planner, allowing subsequent decisions to reflect the actual execution outcome. The loop ends when G is satisfied, the agent explicitly terminates, or the episode budget is exhausted. The resulting trajectory records observations, tool calls, and feed-back as evidence for subsequent skill updates, linking feedback-guided execution to skill evolution across rollouts. 3.2 EMBODIED FEEDBACK -D RIVEN SKILL EVOLUTION 

As the experience-bearing unit of embodied-agent self-evolution, each skill is organized as an exe-cutable hypothesis about how a task should be performed. It captures the relation between changes in the observed scene and the agent’s subsequent behavior: given the current observation and feedback from the previous operation, it specifies how the next operation should be selected and executed. At the same time, a skill is not tied to a particular object identity. It is organized around task-relevant states and manipulation affordances. For example, a grasping skill is not intended for a single object such as a mug, but for different targets that share similar manipulation requirements. This orga-nization separates task intent from its physical realization, allowing the skill to preserve reusable behavioral structure as the environment changes. Effective skill evolution requires more than adding new experience; it requires continual revision of existing knowledge. To prevent erroneous experience from permanently contaminating the skill memory and to avoid uncontrolled append-only accumulation, a skill must be tested through em-bodied feedback during task execution. The system collects scene observations, tool outcomes, intermediate verification signals, and the final task result throughout each rollout. Together, these signals provide multiple forms of evidence about the current skill. Successful trajectories can indi-cate that an operation and its surrounding conditions are reusable, whereas failed trajectories may reveal an unsuitable operation, an incorrect execution order, a missing transition, or a verification condition that no longer holds in the target environment. After a rollout, the agent integrates this evidence to propose a local revision of the current skill. The revision may add a missing operation, replace an unreliable transition, or remove behavior that is no longer supported, while preserving unaffected parts of the procedure. To distinguish evidence-supported improvements from unverified behavioral hypotheses, each can-didate skill is evaluated against the current skill under comparable task conditions. A candidate is consolidated as a new skill version only when it remains valid and improves task execution. If it fails to improve performance or introduces invalid behavior, the current skill remains unchanged and the candidate is excluded from persistent knowledge. Skill evolution is therefore not a simple accumulation of experience, but a feedback-driven process in which behavioral evidence is tested, selectively incorporated, and gradually consolidated into reusable task knowledge. 53.3 FROM A FROZEN POLICY TO A SELF -G UIDED ACTION TOOL 

RoboBridge integrates the fine-grained manipulation capabilities of a pretrained end-to-end action model with the agent’s explicit task procedures. The agent uses the active skill and multimodal con-text to specify a local operation, which the model translates into a short action segment. Operation selection and outcome verification remain explicit in the agent’s execution loop. This organization allows procedural knowledge to be revised independently of the model parameters while retaining pretrained manipulation capabilities. The central execution challenge is to align the model’s generated actions with the requirements of the selected operation. A valid task procedure specifies the intended outcome, but a frozen model can still produce unsuitable behavior under different observations and physical conditions. We ad-dress this discrepancy through inference-time guidance configured by the agent. # 4 EXPERIMENTS 

We organize our experiments around two deployment stages. In the simulation stage, the agent repeatedly interacts with LIBERO-PRO to evolve task skills and evaluates the resulting procedures. In the transfer stage, the skills obtained in simulation are initialized on corresponding real-robot tasks and further adapted from feedback collected in the target environment. For each task in both the simulated and real-world settings, we follow the Embodied Feedback-Driven Skill Evolution process described in Section 3.2 to obtain the skill used for subsequent eval-uation. The agent gathers evidence from multiple training episodes and uses it to generate candidate skills. After evaluation, an accepted candidate is persisted as a new skill version for subsequent deployment. Section 4.1 describes the common experimental configuration and skill evolution protocol. Section 4.2 reports the results on the LIBERO-PRO benchmark, and Section 4.3 evaluates skill transfer and continued adaptation in the real-robot environment. 4.1 EXPERIMENTAL SETUP

We evaluate whether task skills evolved in simulation can be transferred directly to real-robot set-tings and further improved through feedback from physical execution. This evaluation examines whether simulation experience can facilitate adaptation to real-robot tasks and reduce the effort required for debugging. To support reuse across environments, we encapsulate the real robot’s perception, calibration, and control pipelines behind a unified interface, exposing observation spec-ifications and compatible tool interfaces aligned with those used in simulation. We investigate three questions: (1) whether skills evolved in simulation can be applied directly to real-robot tasks with the same or similar task semantics; (2) whether transferred skills can continue to evolve through real-world interaction and improve task performance; and (3) whether simulation skills reduce the exploration and debugging effort required for learning and evolution in the physical environment. As shown in Figure 4, we design three real-robot tasks whose task semantics and high-level opera-tion procedures correspond to existing simulation tasks, while their specific objects and manipulation modes differ. We first apply the skills evolved in simulation directly to the physical tasks, before performing any real-robot evolution, to measure their transfer value. Figure 5 (a) shows that, com-pared with execution without skill guidance, the transferred skills improve the success rates of the three tasks from 4/15 , 2/15 and 3/15 to 9/15 , 7/15 and 7/15 . These results indicate that simulation experience provides effective initial behavioral guidance for real-robot execution. We then initialize real-robot adaptation with the transferred skills. For the performance evaluation in Figure 5 (a), we run 10 real-robot episodes per task and perform one round of skill evolution after every episode. Execution feedback is used to revise the skills for the target environment and its manipulation conditions. The adapted skills achieve 15 /15 , 14 /15 , and 15 /15 successful trials on the three tasks, respectively. These improvements over direct transfer show that physical interaction can further refine the transferred skills after deployment. We presented RoboBridge, a self-evolving embodied agent framework for transferring procedural skills from simulation to reality and adapting them through execution feedback. Reusable, revisable skills guide tool selection and outcome verification, while inference-time guidance adapts action generation without updating the underlying policy. Experiments on LIBERO-PRO and three real-robot tasks show that simulation-evolved skills can provide useful initialization for physical execu-tion and continue to improve through real-world feedback, reducing adaptation effort compared with evolution from scratch. Our current evaluation adopts Codex with GPT-5.5 as the coding-agent con-figuration. A direction for future work is to explore RoboBridge with a broader range of foundation models and agent harnesses, further examining its applicability across different model capabilities and agent execution frameworks. RoboBridge separates observation construction from action selection through an environment adapter. In centralized-perception mode, the adapter supplies an initial observation after reset and refreshes it after each action-tool invocation. The planner receives the task instruction, procedural skills, current observation, and execution feedback, then selects the next tool and its arguments. Segmentation, geometric reconstruction, and observation packaging are handled by the adapter. The planner is responsible for task decomposition, object selection, motion offsets, and outcome verifi-cation. This division allows sensing and control implementations to vary across environments while preserving the observation–action–verification loop used by the skills. In simulation, observation construction begins with a scene inventory initialized from the camera images and task instruction. The inventory provides entity identities and descriptions for subsequent segmentation. After each action, the adapter associates the resulting masks with current metric ge-ometry and extracts measured reference points. Each point retains its entity identifier, source camera, pixel location, and capture step. Missing or unreliable measurements are represented through avail-ability and uncertainty fields. The resulting snapshot describes the scene and robot state; target– destination assignments, grasp offsets, and end-effector goals are determined by the planner. For example, a measured point on an object’s upper surface supplies a geometric reference, while the planner determines the approach and grasp positions using the task, skill, and current observations. The action library provides a common interface between the planner’s subtask decisions and robot execution. It covers Cartesian motion, orientation adjustment, gripper control, and policy-based manipulation, as summarized in Table 3. The planner uses the current observation and procedural skill to select an operation and express its intent through a position, a pose, a gripper command, or a language instruction. The environment adapter translates the request into executable robot actions. This organization lets skills describe how operations should be composed while delegating their low-level execution to the corresponding tools. Geometric tools support operations with explicit spatial objectives, including approaching an object, aligning the end effector, transporting a held object, and positioning it for release. Orientation and gripper tools provide complementary control over alignment and object handling. Policy-based tools supply learned manipulation behavior for grasping and other contact interactions. A task procedure can combine geometric positioning with policy-based manipulation, with the planner selecting the appropriate tool according to the current subtask and observed state. When guidance is activated, the agent configures a reward specification from the subtask objective, execution constraints, and observed feedback. This specification steers action generation toward the intended operation while keeping the policy parameters fixed. The policy produces short action sequences from current sensor observations, and the agent evaluates the resulting progress at tool boundaries to inform subsequent invocations. The policy thus supplies continuous manipulation capability, while the agent controls its invocation and the guidance appropriate to the current operation. # C LIBERO-PRO B ENCHMARK AND EVALUATION PROTOCOL 

LIBERO-PRO augments LIBERO with controlled variations in task requirements and scene config-urations. Our evaluation covers the SPATIAL, OBJECT, GOAL, and LIBERO-10 families, which provide complementary settings involving spatial relationships, object identities, goal conditions, and longer manipulation sequences. Together, these families allow us to examine procedural skills across different manipulation requirements under a common benchmark framework. Each family is evaluated under two perturbation conditions, T and S. In the task or instruction-redirection condition T, the instruction specifies another valid target object or goal condition. The agent must therefore interpret the revised objective and bind its procedure to the appropriate objects. In the swap or position-swap condition S, object starting locations are exchanged or rearranged while the instruction is kept unchanged. This condition requires the agent to ground its actions in the current layout. The two conditions examine adaptation to changes in task meaning and spatial configuration, respectively. For every task, seeds 11–20 are assigned to training for skill evolution, seeds 21–25 to validation, and seeds 1–10 to testing. Training episodes supply the execution feedback used to construct candidate skill revisions. The validation gate compares a candidate with the current skill under matched initial conditions and determines whether the revision is retained. The selected skill is subsequently fixed throughout testing. The three seed sets are disjoint, so test initial states are excluded from both skill-update evidence and validation decisions. Reported success rates are calculated from test episodes alone. A test rollout starts from the initial state specified by its task and seed. RoboBridge receives the task instruction and initial observation, then uses the selected skill to organize tool execution and verify intermediate outcomes. Observations and execution feedback are refreshed as the rollout proceeds, while the skill itself remains unchanged. The rollout continues until the task succeeds, execution is stopped, or the allotted budget is exhausted. This distinction allows the planner to respond to the current scene during testing without performing further skill evolution. The four families and two perturbation conditions form 4 × 2 = 8 evaluation groups. Each group contains 10 tasks, with one test rollout for each of the 10 test seeds per task. RoboBridge uses a frozen π0.5 policy as its contact-rich action primitive in both simulation and physical deployment. The two deployments use different checkpoints because the simulated and real environments provide different robot embodiments, sensor layouts, state representations, and control interfaces. In simulation, we use the RLinf LIBERO checkpoint, denoted πRLinf , while the physical experiments use the OpenPI DROID checkpoint, denoted πDROID (Intelligence et al., 2025; Yu et al., 2025). During each policy invocation, the agent may construct an inference-time reward specification from the current subtask, execution constraints, and observed feedback. This reward guidance steers the generated action segment without updating the VLA parameters. D.1 πRLinf : RL INF LIBERO C HECKPOINT 

Architecture. πRLinf is the LIBERO-specific π0.5 checkpoint released with RLinf, corresponding to the full-shot pi05-libero130 model. The policy combines visual observations, language instructions, and robot state before producing continuous robot actions. Within RoboBridge, the planner specifies the current operation through a task or subtask instruction, while the agent can supplement this context with an inference-time reward specification. The policy then converts the multimodal context and the guidance signal into a short manipulation segment. 

Input, Guidance, and Action Interface. For LIBERO execution, the policy receives an external RGB view, a wrist-camera RGB view, proprioceptive state, and a language prompt. The environment adapter maps these fields to the input structure expected by the π0.5 implementation and applies the normalization statistics associated with the checkpoint. Before a guided invocation, the agent inter-prets the active skill and execution feedback to define the desired local outcome, relevant constraints, and undesirable behaviors. This information is expressed as an inference-time reward specification and used to steer action generation during the current policy call. The resulting action chunk is then executed before the next observation is returned to the planner. 

Action Modeling. The inspected LIBERO service produces a short chunk of continuous actions rather than a single control command. Each chunk contains seven-dimensional environment ac-tions and is executed before the planner receives the refreshed observation and execution status. The reward guidance operates during this action-generation process: it evaluates whether candidate behavior is consistent with the local subtask and biases the generated segment toward the desired outcome. The guidance is therefore local to the current invocation and does not become a permanent modification of the policy. 

Training and Deployment. The checkpoint is adopted without additional policy training or target-domain fine-tuning. Its parameters are loaded once and kept in evaluation mode. During guided in-ference, the policy parameters remain frozen; gradients, when used, are computed only with respect to the candidate action sequence. The reward specification supplied by the agent is an inference-time control signal rather than a supervised training label or a parameter-update objective. Skill evolution consequently operates at the procedural level, modifying operation ordering, target binding, tool selection, and verification conditions, while reward-guided inference adjusts the execution of the selected operation. 

Performance and Role in RoboBridge. When used directly as a policy-only baseline on LIBERO-PRO, πRLinf obtains an overall success rate of 50 .0% under the reported evaluation pro-tocol. This result provides a reference for separating the contribution of the frozen action policy from the contribution of procedural planning, skill evolution, and inference-time reward guidance. In RoboBridge, πRLinf supplies fine-grained manipulation capability, while the agent determines the operation to execute, constructs guidance when necessary, and verifies whether the resulting state satisfies the intended subtask. D.2 πDROID : O PEN PI DROID C HECKPOINT 

Architecture and Checkpoint. πDROID is the OpenPI π0.5 checkpoint used for physical-robot execution. It preserves the same general vision-language-action formulation as the LIBERO policy, 17 but is supplied through a DROID-oriented deployment stack. The physical agent does not invoke the checkpoint with a fixed open-loop procedure alone. Instead, it provides the current manipulation instruction together with an inference-time reward specification when additional behavioral steering is required. The checkpoint remains unchanged while the guidance signal adapts action generation to the current physical context. 

Observation, Guidance, and Action Processing. The physical policy service consumes an exter-nal view, a wrist view, robot state, and a language instruction describing the current manipulation operation. The agent first obtains a fresh observation and positions the end effector for the intended operation. It then determines whether the policy should be guided and, if so, specifies the desired in-teraction outcome and physical constraints through the reward signal. The DROID policy generates a short action chunk under this instruction and guidance, which is executed through the physical control interface. After execution, refreshed images and robot state are returned for verification before another policy call is permitted. 

Frozen Use and Agent Coordination. The DROID checkpoint remains frozen during real-world skill evolution. The agent controls the conditions under which the policy is invoked: it selects the target object, determines the local operation, checks that the preceding positioning action suc-ceeded, and constructs the reward specification when the action requires additional steering. The reward signal is used only during inference and does not create a new training update for the policy. Subsequent skill revisions operate on the surrounding procedure, including pre-positioning, action ordering, recovery behavior, and outcome verification. 

Role in Physical Transfer. In the real-robot stage, πDROID provides the low-level manipulation capability required to execute transferred procedures. RoboBridge transfers the task-level organiza-tion of the skill from simulation, while the physical adapter and the agent-generated reward guidance determine how each local operation is realized under the target robot’s observations and dynamics. Execution feedback is retained for subsequent skill revision, allowing the transferred procedure to be refined without retraining the entire VLA model. The contribution of πDROID is therefore eval-uated as part of the complete real-robot transfer and adaptation process rather than as an isolated policy-only score. 

# E PROMPT , S KILL , AND STRUCTURED ARTIFACT ORGANIZATION 

RoboBridge separates agent behavior into three persistent layers: environment-specific system prompts, executable procedural skills, and structured execution artifacts. The system prompts define how the agent interprets observations, selects tools, and verifies outcomes. Skills describe reusable task procedures and their recovery conditions. Structured artifacts record the observations, tool calls, feedback, and evaluation results generated during an episode. The following examples present the organization and semantics of these components while omitting implementation-specific prompt text. E.1 SIMULATION PLANNER PROMPT 

The simulation system prompt defines the common planner contract used during LIBERO-PRO execution. It instructs the agent to reason from the newest observation, issue at most one physical operation per response, and wait for the resulting observation before selecting the next operation. It also describes the available geometric and policy-based tools, the distinction between primitive completion and task success, and the requirement to use the benchmark completion predicate for final evaluation. The prompt does not encode a complete task procedure; task-specific behavior is supplied through the active skill. 

Prompt 1: Simulation Planner System Prompt 

Purpose: Organize task execution in the simulator. 18 Core semantics: Use the newest observation; select one operation; wait for execution feedback; verify the resulting state. 

Tool semantics: Combine geometric motion tools with policy-based manipulation tools. Tool completion is not equivalent to task success. 

Evaluation rule: Use the benchmark task-completion predicate to determine the final out-come. E.2 PHYSICAL -R OBOT SYSTEM PROMPT 

The physical-robot system prompt extends the simulation contract with requirements imposed by hardware execution. It requires the agent to inspect a fresh external and wrist observation before acting, respect workspace and motion constraints, and stop when execution or sensing becomes unreliable. A policy-based action call is allowed only after the robot has been positioned for the intended operation and a new observation has been obtained. The prompt also makes clear that closing the gripper, completing an action chunk, or returning from a tool does not prove that the intended object interaction succeeded. 

Prompt 2: Physical-Robot Execution Prompt 

Purpose: Add hardware-aware constraints to the planner loop. 

Observation rule: Inspect the newest external and wrist views before making a physical decision. 

Policy-call gate: Position the end effector successfully and refresh the observation before invoking the policy action. 

Failure rule: Stop the episode when execution, localization, or observation reliability is lost. E.3 SKILL -E VOLUTION SYSTEM PROMPT 

The skill-evolution system prompt is used after one or more training rollouts. It asks the agent to compare the current skill with the observed execution evidence, identify the local cause of failure or improvement, and propose a bounded revision. Candidate revisions may modify an operation, transition, recovery condition, or verification rule while preserving unaffected parts of the skill. The prompt also requires the candidate to be evaluated against the incumbent skill before persistence. A candidate that does not improve execution or introduces unsupported behavior is rejected. 

Prompt 3: Skill-Evolution System Prompt 

Purpose: Convert rollout evidence into a controlled skill revision. 

Evidence: Read observations, tool outcomes, intermediate feedback, and the final task result. 

Revision scope: Add, replace, or remove a local operation, transition, recovery condition, or verification rule. 

Persistence rule: Retain a candidate only after comparison with the current skill under matched evaluation conditions. E.4 STORED SKILL STRUCTURE 

A stored skill is represented as a compact procedural document rather than as a raw transcript. It contains the task intent, applicable conditions, expected observations, ordered operations, verifica-tion criteria, and recovery behavior. The skill is written around task-relevant states and affordances, 19 so that object names or scene-specific coordinates do not become the only source of generalization. The following schematic shows the organization of a saved skill without reproducing a complete task-specific procedure. 

Artifact 1: Stored Skill Schema 

Skill ID: object transfer 

Intent: Transfer a selected object to its designated destination. 

Preconditions: 

• The target and destination are observable. • The robot is in a reachable starting configuration. 

Procedure: 

1. Bind the instruction to the current target and destination. 2. Select a suitable positioning or manipulation operation. 3. Execute the local action and refresh the observation. 4. Verify the intermediate state before continuing.

Recovery: Re-observe, revise the local operation, or terminate when the required evidence is unavailable. E.5 SKILL VERSIONING AND VALIDATION 

Each accepted skill is associated with a version identifier and the evidence used to produce it. During evolution, the incumbent skill remains available as a fallback, while a candidate skill is evaluated separately. The candidate is promoted only when it satisfies the validity checks and improves the selected execution criterion. Rejected candidates are retained as audit records rather than merged into the active skill. This versioned organization prevents a single failed rollout from permanently altering the procedural memory.

Decision: accepted or rejected

The simulation and physical prompts share the same high-level behavioral contract but differ in their environment-specific constraints. The simulation prompt emphasizes benchmark interaction and predicate-based completion, whereas the physical prompt additionally enforces fresh sensing, pre-positioning before policy invocation, hardware-aware stopping, and operator-based outcome la-beling. The skill format and update protocol remain shared across the two domains. This organiza-tion allows a skill evolved in simulation to be transferred as a procedural object while adapting its environment-specific execution conditions through the physical prompt and feedback records. 21
