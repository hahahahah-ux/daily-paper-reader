## 摘要
预训练视频世界模型能够为一个场景给出许多可能的未来，但机器人必须实现与任务条件精确对应的那个未来。为了将世界模型转化为可执行的机器人策略，现有方法利用大规模机器人数据和计算资源对庞大的世界模型骨干进行微调。我们挑战这一现状，认为昂贵的部分已在世界模型预训练中完成，因为视频世界模型的表示空间已经铺陈出多样的潜在未来。在这种情况下，剩下的就是选择能够完成任务的未来，并读出实现该未来的动作。我们将此任务形式化为实际化（actualization），即在冻结世界模型提供的先验之上学习任务条件下的选择与实现。这可以通过一个微型实际化器（actualizer）模型来解决。我们实现了 RoboActualizer，其在冻结的世界模型编码器之上仅有少至 6000 万参数。该实际化器由两个轻量级 DiT 专家组成，通过流匹配联合预测未来潜变量和动作。该模型可以完全在单块峰值内存为 32 GB 的 GPU 上训练。与现有的 WAM 和 VLA 相比，RoboActualizer 的可训练参数最多少 100 倍，却在 LIBERO、LIBERO-Plus、RoboTwin 2.0 等仿真基准以及两个真实世界平台上的五项任务中取得了出色性能，且延迟低至 39 ms，可支持实时控制。

## Abstract
A pretrained video world model admits many plausible futures for a scene, but a robot must realize the exact task-conditioned one. To turn world models into executable robot policies, existing methods fine-tune the heavy world model backbone using large-scale robot data and computational resources. Challenging this status quo, we argue that the expensive part has already been paid in the world model pretraining since the representation space of a video world model lays out the diverse potential futures. In this case, what remains is to select the future that accomplishes the task and to read out the actions that realize it. We formalize this task as actualization, which learns a task-conditioned selection and realization on top of a prior supplied by a frozen world model. This can be solved by a tiny actualizer model. We implement RoboActualizer with as few as 60M parameters on top of a frozen world model encoder. The actualizer is composed of two lightweight DiT experts that jointly predict future latents and actions by flow matching. The model can be trained entirely on a single GPU with 32 GB peak memory. With up to 100x fewer trainable parameters than existing WAMs and VLAs, RoboActualizer reaches great performance on simulation benchmarks including LIBERO, LIBERO-Plus, RoboTwin 2.0 and five tasks on two real-world platforms, with a low latency of 39 ms that allows real-time control.

## 1. 核心问题与研究动机

- **背景**：在互联网规模视频上预训练的视频世界模型（如 V-JEPA、Wan 等）已成为强大的世界演化预测器，其表征空间天然编码了场景的多种合理未来（"无限可能的世界"）。
- **矛盾**：机器人最终必须完成**一个特定任务**并输出精确动作，而世界模型本身并不承诺某一种未来。
- **现有方案的两难**：
  - **规划类方法（MPC）**：冻结世界模型，测试时反复想象 rollout 搜索动作，导致控制频率低，且目标通常是目标图像或手工设计代价，而非语言指令。
  - **世界-动作模型（WAM）/ VLA**：微调庞大主干，将动作预测吸收进世界模型，但需要大量机器人数据与算力（如 Fast-WAM 6B 参数、约 112 GPU 小时）。
- **核心洞见**：昂贵的部分已在世界模型预训练中支付完毕；表征空间已铺陈出所有潜在未来，机器人剩下的只是**选择**能完成任务的未来，并**读出**实现它的动作。选择远比建模动力学便宜。
- **形式化任务**：将这一过程命名为 **actualization（实际化）**——在冻结世界模型提供的先验之上，学习任务条件下的选择与实现。

## 2. 方法论

### 2.1 核心思想：分工与贝叶斯分解

- 世界模型 `g_ϕ` 将短时观测片段编码为隐表征 `z_t = g_ϕ(x_{t−∆:t})`，其中已包含场景动力学与可行未来集合 `F(z_t) = ∪_ℓ F_ℓ(z_t)`。
- 给定指令 `ℓ`，未来与动作的联合分布按贝叶斯法则分解为三部分：
  - **先验**：`p(z⁺_{t:t+H} | z_t)`，由冻结世界模型提供；
  - **选择**：`p(ℓ | z⁺, z_t) / p(ℓ | z_t)`，需学习，将先验重加权到任务 `ℓ` 对应的未来成分；
  - **实现**：`p(a_{t:t+H} | z⁺, z_t, ℓ)`，需学习，把选中的未来映射为动作。
- 目标函数为最大似然（式 4），但由于 `ϕ` 冻结、先验几何已给定，学习难度由"选择"而非"场景动力学"决定，因此极小的 `q_θ` 即可胜任。

### 2.2 关键技术细节

- **冻结世界模型**：采用 V-JEPA 2.1（ViT-L/16，约 300M），以视频分支（tubelet=2）编码 4 帧片段，取最后一个时间组作为 `z_t`（392×1024 tokens），未来目标为 `t+4, t+8, t+12, t+16` 处的隐变量，全部离线缓存，训练时无需前向世界模型。
- **轻量实际化器**：两个 DiT 专家组成 **Mixture-of-Transformers（MoT）**：
  - **潜变量专家**预测任务条件下的未来隐变量；
  - **动作专家**预测实现该未来的动作块（16 步）。
  - 两专家权重独立，通过共享自注意力交互；指令由冻结 UMT5 编码，与本体检出状态一起经交叉注意力注入。
- **x-prediction（clean-sample 参数化）**：网络直接预测干净 token，而非 v-prediction；原因是 V-JEPA 表征空间低秩（`d_model=384` 保留 93.8% 方差），而 v-prediction 目标含全秩各向同性高斯噪声，窄网络无法捕捉。
- **训练损失**（在速度空间计算）：
  - `L = L_a + λ_z L_z`，其中 `L_a = E[‖(a − â)/(1−τ_a)‖²]`，`L_z = E[‖(z⁺ − ẑ⁺)/(1−τ_z)‖²]`；
  - 噪声 token 由 `ã_τ = (1−τ)ϵ + τa` 构造，采用 shifted rectified-flow 调度（1000 离散噪声级，s=5），分母下限 0.05。
- **推理**：编码器每次观测仅前向一次，去噪只在轻量头部迭代 K 步；丢弃未来潜变量预测（action-only 模式）并缓存干净帧中间特征，实现 >25 Hz 实时控制。

## 3. 实验设计

### 3.1 数据集 / 场景与 Benchmark

- **仿真基准**：
  - **LIBERO**：Spatial、Object、Goal、Long 四个任务套件，每套件 10 任务、每任务 50 次试验（每 checkpoint 2000 episodes）；联合训练 1712 条演示、277,713 帧。
  - **LIBERO-Plus**：LIBERO 的扰动变体，7 个扰动维度（Camera、Robot、Language、Light、Background、Noise、Layout），共 10,030 个扰动实例，每实例单次评估；仅在 LIBERO 原始演示上训练，不做额外增广。
  - **RoboTwin 2.0**：50 个双臂操作任务，每任务随机采样 50 条演示，在 Clean 与 Random 两种设置下各 25 episodes（共 2500 评估 episodes），报告平均成功率。
- **真实平台**：
  - **FANUC CRX-10iA**（单臂+夹爪）：Mug Hanging、Multi-stage Cooking 两任务（约 100 条演示/任务）。
  - **Unitree G1**（人形+双臂灵巧手 Dex3-1）：Box Packing、Cup Insertion、Plate Handover 三任务（约 170 条演示/任务）。

### 3.2 对比方法

- **仿真**：OpenVLA（279M）、π0（3.3B）、π0.5（3.3B）、UniVLA（123M）、Motus（5.9B）、WorldVLA（7.0B）、Fast-WAM（6.0B）、DC-WAM（6.0B）、LingBot-VA（5.3B）等 VLA/WAM 基线。
- **真机**：π0.5（VLA 基线，微调自预训练权重）与 Fast-WAM（WAM 基线，从零训练）。

### 3.3 消融实验

- 是否联合预测潜变量（latent prediction 开/关）；
- 不同表征空间（DINOv3、WAN VAE、V-JEPA 单帧/视频）；

## 4. 资源与算力

- **训练**：全部在**单张 NVIDIA PRO 6000 GPU（32 GB 峰值内存）**上完成，LIBERO 上约 **15 小时**；实际化器仅 60M 可训练参数，训练在缓存的 V-JEPA 潜变量上进行，无实体预训练。

## 6. 主要结论与发现

- **性能**：60M 参数的 RoboActualizer 在 LIBERO 上达 **98.0%** 平均成功率，超过多个 100× 参数量的 VLA/WAM；LIBERO-Plus 达 **63.1%**（Fast-WAM 51.5%，DC-WAM 60.9%）；RoboTwin 2.0 达 **58.8%**（π0.5 31.4%、Fast-WAM 41.9%）。
- **真机**：FANUC 上 Mug Hanging 95%、Cooking 60%（Fast-WAM 10%/15%）；G1 上 Box 77%、Cup 83%、Plate 90%（π0.5 57%/50%/30%）。
- **效率**：39 ms 延迟，支持实时控制；训练成本比 6B 级 WAM 低约一个数量级。
- **关键发现**：
  - 冻结 V-JEPA 表征本身不足（仅接动作头时 LIBERO-Plus 从 60% 跌至 17.9%），**联合预测未来潜变量**是激发世界模型预测能力的关键；
  - 潜空间的**未来预测能力比表征能力更重要**（DINOv3、单帧 V-JEPA 表现均差）；
  - **扩大冻结世界模型比扩大 actualizer 更有效**（ViT-B→ViT-L 提升明显，DiT-S→DiT-B 提升有限），印证"actualizer 只需选择而非想象"。

## 7. 优点

- **思想简洁优雅**：用贝叶斯分解将"世界建模"与"任务选择+动作读出"明确解耦，把昂贵先验一次性摊销到多任务。
- **参数与算力效率极高**：60M 可训练参数、单卡 32 GB、15 小时训练，显著降低 WAM 训练门槛；推理 39 ms 满足实时控制。
- **表征分析有说服力**：通过 PCA 累计解释方差（d=384 保留 93.8%）为"窄 actualizer 足够"提供定量依据，并据此选择 x-prediction。
- **泛化性验证充分**：LIBERO-Plus 的 7 维扰动、RoboTwin 的 Clean/Random 设置、跨单臂/双臂/人形平台的验证，显示冻结表征可保留鲁棒性。
- **公平性意识**：统一种子、固定初始状态、无测试时调优，并报告缓存特征训练带来的可复现细节（附录 B 详尽）。

## 8. 不足与局限

- **世界模型覆盖单一**：仅验证了 V-JEPA 2.1，未与其他视频世界模型（如像素生成式、DINO-WM 等）组合，泛化结论受限。
- **基准覆盖不完整**：作者自述因资源限制未在完整 RoboTwin 2.0 上实验（每任务仅 50 条演示），真机任务数较少，统计置信度有限。
- **依赖冻结编码器质量**：方法本质上是"读出"冻结表征，若上游世界模型在目标域表征不佳或域偏移过大，轻量 actualizer 难以补偿。
- **架构与超参敏感**：宽头导致性能下降（48.5% vs 60.0%），说明设计选择并非无关紧要；x-prediction 与 MoT 均为必要组件。
- **评估细节**：LIBERO-Plus 每实例仅一次评估，可能引入噪声；部分基线（如 DC-WAM）无开源代码，延迟无法测量。
- **应用限制**：真机部署需要预先收集演示并离线缓存潜变量；对高频控制（如 50 Hz RoboTwin）需调整时间步长，通用性有待进一步验证。
