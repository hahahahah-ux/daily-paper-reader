## 摘要
视觉-语言-动作（VLA）模型、世界-动作模型（WAMs）以及离线强化学习方法正在迅速拓展具身策略的设计空间，然而将这些算法转化为可靠的机器人系统，仍受限于碎片化的数据格式、训练栈、评估协议、推理运行时以及面向具体具身形态的接口。我们提出 FluxVLA 引擎，一个开放、配置驱动的平台，可将异构的具身策略组件转化为可复现的从数据到部署的工作流。FluxVLA 并非引入另一种策略模型，而是为数据集、视觉-语言模型与世界模型、动作头、奖励或优势加权学习、分布式训练、仿真评估、优化推理以及机器人操作器标准化接口。该引擎进一步集成了可组合的双臂仿真、可扩展的自动数据生成，以及与模型解耦的人在回路中的 rollout、接管、纠正收集和奖励标注。为实现响应式的物理执行，它将实时分块（Real-Time Chunking, RTC）与加速推理后端、轻量级远程 GPU 服务以及可配置的轨迹后处理相结合。这些能力通过共享且可审计的契约，将离线学习、仿真验证、在线纠正和真机执行连接起来。因此，FluxVLA 旨在解决那些将有前景的具身学习算法与可复现评估及可靠部署隔离开来的工程瓶颈。代码见 https://github.com/FluxVLA/FluxVLA

## Abstract
Vision-language-action (VLA) models, world-action models (WAMs), and offline reinforcement learning methods are rapidly expanding the design space of embodied policies, yet turning these algorithms into reliable robot systems remains constrained by fragmented data formats, training stacks, evaluation protocols, inference runtimes, and embodiment-specific interfaces. We present $\mathrm{FluxVLA}$ Engine, an open, configuration-driven platform that turns heterogeneous embodied-policy components into a reproducible data-to-deployment workflow. Rather than introducing another policy model, $\mathrm{FluxVLA}$ standardizes interfaces for datasets, visual-language and world models, action heads, reward- or advantage-weighted learning, distributed training, simulation evaluation, optimized inference, and robot operators. The engine further integrates compositional dual-arm simulation, scalable automatic data generation, and model-decoupled human-in-the-loop rollout, takeover, correction collection, and reward annotation. For responsive physical execution, it combines Real-Time Chunking (RTC) with accelerated inference backends, lightweight remote GPU serving, and configurable trajectory post-processing. Together, these capabilities connect offline learning, simulation validation, online correction, and real-robot execution through shared and auditable contracts. $\mathrm{FluxVLA}$ therefore targets the engineering bottlenecks separating promising embodied-learning algorithms from reproducible evaluation and dependable deployment. Code is available at https://github.com/FluxVLA/FluxVLA

## 2. 方法论

### 2.1 核心思想与四大原则
- **统一（Unification）**：单一配置描述数据、模型、优化、评估与部署。
- **模块化（Modularity）**：通过注册表（registry）与显式接口解耦实现。
- **可部署（Deployability）**：保留模型与预处理路径，仅替换环境/机器人相关执行层。
- **可复现（Reproducibility）**：记录解析后的实验状态，导出可评估/部署的 artifact。

### 2.2 系统架构（五层职责）
- **数据层**：存储 episode → 规范化样本字典（composable transforms + collators）。
- **模型层**：样本字典 → 训练损失或推理动作块。
- **执行层**：分布式设置、优化、checkpoint、评估循环、运行时状态。
- **服务层**：策略与机器人跨进程/机器传输观测与动作。
- **操作器层（Operator）**：框架状态/动作契约 ↔ 仿真器或机器人 SDK。

### 2.3 数据管道
- 统一为 **LeRobot 兼容 Parquet** 表示（低维信号存 Parquet，视频按 episode 引用），支持 v2.1 与 v3 metadata。
- **Episode 感知的时序采样**：从同一 episode 内构造"当前观测 + 未来动作块 + 多帧视觉上下文"，采样不跨 episode 边界，mask 防止 padding 贡献监督。
- **规范化样本表示**：统一视觉观测、本体状态、语言指令、动作目标、有效性掩码与可选 metadata。
- **统计与归一化**：从数据集 metadata 推导统计量，训练时保存至模型 artifact，推理时复用，防止训练/推理不一致。
- **多源采样与批处理**：支持单源、拼接源、分组源；确定性分片到分布式 rank 与 dataloader worker；支持平衡采样与采样权重。

### 2.4 模型架构
- **BaseVLA** 定义槽位：视觉 backbone、语言 backbone、集成 VLM、模态 projector、action head；每个槽位由独立 registry 与配置构建。
- **兼容两类路径**：
  - 组合式（decomposed）：如 vision encoder + projector + causal LM + action head。
  - 原生 wrapper（native）：如 π0 的耦合 LM + action expert、WAM 的视频 VAE + 多 diffusion-transformer 流、Cosmos3 的 mixture-of-transformers。
- **统一契约**：`forward(**batch) -> losses` 与 `predict_action(**batch) -> action chunk`。
- **动作生成接口**：
  - 自回归离散动作（OpenVLA 路径）：动作 tokenizer 量化，masked next-token 交叉熵。
  - 连续流匹配（π0/π0.5/SmolVLA/GR00T）：学习速度场，训练为 masked MSE，推理数值积分。
  - 时序/世界-动作模型（DreamZero、DiT4DiT、FastWAM、Cosmos3）：视频 latent + 语言 + 状态 + 动作联合建模，报告视觉动力学与动作损失分量。
- **初始化与适配**：支持 safetensors/分片目录/PyTorch checkpoint，可配置名称映射，strict loading；模块可独立冻结；支持全参数训练与 LoRA；每个 VLA 提供 FSDP wrapping 策略。

### 2.5 仿真评估
- 注册式 evaluator 从 checkpoint 与 run-local artifact 重建策略与评估设置，使用 run-local 统计恢复归一化契约。
- 每个 episode：环境 reset → 在线 transform → 预测 H 步 action chunk → 执行前 K 步（1 ≤ K ≤ H），每步后检查成功/终止。
- 支持 **LIBERO** 与 **RoboCasa GR-1**：LIBERO 直接传动作向量；RoboCasa 使用 29-D 动作接口（7-D 左臂 + 6-D 左手 + 7-D 右臂 + 6-D 右手 + 3-D 腰），支持原生 FluxVLA 顺序与官方 GR00T N1.5 顺序。
- 分布式：按 episode 或 task 分片，聚合总/每任务成功数与时长；保留 rank 日志、结构化摘要、per-task 结果与可选 rollout 视频。

### 2.6 真机推理
- **四阶段 runner 契约**：观测预处理 → 动作预测 → 动作后处理 → 轨迹执行。
- **观测同步**：operator 按时间戳同步多传感器消息，维护有界缓冲，监控可用性/新鲜度/更新率。
- **本体感知动作执行**：operator 负责动作块验证、转换为可执行命令轨迹、同步/异步派发。
- **远程 GPU 推理**：ZeroMQ request-reply，机器人端保留传感器采集与命令发布，GPU 服务端执行在线 transform、预测、反归一化；支持 MessagePack/Protocol Buffers/NumPy/JPEG 压缩；客户端 profiling 序列化、往返、推理、反序列化与总延迟。
- **安全边界**：FluxVLA 本身不实现碰撞避免、工作空间约束、力矩限制或认证急停控制器，这些由机器人 SDK 与部署流程负责。

### 2.7 推理加速
- **推理模型替换**：配置选择与训练结构兼容但替换部分模块的推理实现（如 GR00T 的 EagleInferenceBackbone + FlowMatchingInferenceHead；π0.5 的 PI05FlowMatchingInference 整体替换），checkpoint 不变。
- **核融合与函数化**：Triton 融合归一化、投影、激活、注意力、位置嵌入；CUDA 自定义算子（cublasLt GEMM+bias/residual、rotary embedding）。
- **静态缓冲与 CUDA Graph**：物化权重与最大形状缓冲，首次预测 warm-up + capture，后续 replay；GR00T 仅捕获 action head 去噪路径，π0.5 捕获完整 vision-to-action 管道。
- **数值与配置契约**：优化后端应保持外部行为一致（相同观测语义与连续动作布局），但不要求逐位复现；需比较动作空间误差与轨迹/任务行为。

### 2.8 实时分块（RTC）
- **时序对齐**：计算 `δ = (t_query - t_ref) / Δt`，线性重采样剩余轨迹，clamp 前缀长度 L。
- **Training-time RTC**：
  - 训练阶段：模拟延迟条件化，前 d 个动作位置设为 clean-time，掩码其重建损失：
    - `t'_j = t_clean (j < d), t (j ≥ d)`
    - `m̃_j = m_j · 1{j ≥ d}`
  - 推理阶段：前缀条件化，前 L 个位置初始化为对齐的先前动作，每次去噪更新后恢复。
- **Test-time RTC**：
  - VJP 版本：对前缀一致性误差通过去噪器求导，用 vector-Jacobian product 作为速度修正（需推理时梯度，增加计算/内存）。
  - 直接近似：将加权前缀误差直接加到预测速度，不通过去噪器求导（实现特定简化）。
  - 支持指数、线性、常数 1、零衰减权重。
- **与加速推理交互**：RTC 不能破坏 CUDA Graph 固定形状假设；加速 GR00T head 预分配 prefix-action/mask/timestep 缓冲；当前加速实现支持 Training-time RTC 的前缀条件化，VJP 与直接近似仍在 eager 路径。

### 2.9 轨迹后处理
- 作为 runner 侧可选阶段，位于反归一化与命令执行之间，仅作用于配置的连续自由度（gripper/suction 等离散通道保留本体特定处理）。
- **Joint-space MPC**：以去归一化策略输出为参考轨迹，优化位置/速度/加速度/jerk，目标含跟踪项、正则项、终端位置与终端速度项；服从离散三重积分器与箱约束；用 OSQP 求解，每关节独立并并行。
- **Ruckig 滤波**：在线轨迹生成，满足速度/加速度/jerk 约束；tracking 模式跟随滚动命令流，settle 模式可继续至静止再重采样。
- **跨 chunk 拼接**：保留先前处理轨迹及起始时间与命令周期，新 chunk 到达时按时间戳采样，前 S 个样本作为 stitch 前缀，从 stitch 边界位置/速度/加速度开始优化。
- **与 RTC 关系**：顺序而非竞争——RTC 在策略查询内部条件化下一归一化动作块，后处理对去归一化结果施加关节空间边界并拼接；RTC 减少新 chunk 变化，后处理约束可执行命令。

## 3. 实验设计

### 3.1 数据集与场景
- **仿真 benchmark**：
  - **LIBERO**：Spatial、Object、Goal、Long（libero_10）四个 suite。
  - **RoboCasa GR-1**：24 个任务，分 Cabinet、Drawer、Microwave 与 Generalization 组，每组 50 trials。

  - **ARM 研究**：八阶段 AgileX ALOHA 毛巾折叠任务，120 秒超时，训练集 972 episodes（809 expert + 163 DAgger）。

### 3.2 对比方法

- **推理加速**：GR00T 与 π0.5 的 baseline vs 加速实现，跨 A100、RTX 5090、RTX 4090、AGX Orin 64GB。
- **数值对齐**：GR00T action head 的 plain 与 Training-time RTC 路径，随机权重对比。
- **轨迹后处理**：Joint MPC vs Ruckig filter，12-DoF、50 步合成轨迹，Intel Xeon Platinum 8336C CPU。
- **真机**：GR00T N1.5 vs π0.5（ALOHA、Oli）；ARM 研究中 BC vs RA-BC（SARM）vs AW-BC（ARM）。

- **轨迹后处理**：Joint MPC tracking 平均 4.90 ms；Ruckig tracking 平均 1.17 ms（约 4.19× 更快）。
- **ALOHA**：GR00T N1.5 36/110（32.73%），π0.5 70/110（63.64%）。
- **Oli**：箱体运输阶段 1–3 完成率 GR00T N1.5 60.0% vs π0.5 60.7%；全任务 6.7% vs 32.8%；糖果抓取 40.5% vs 62.5%；篮子玩具抓取 36.3% vs 29.7%。
