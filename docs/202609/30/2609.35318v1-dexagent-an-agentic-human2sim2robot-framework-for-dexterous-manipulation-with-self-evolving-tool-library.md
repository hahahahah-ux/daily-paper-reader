## 摘要
人类视频为灵巧机器人操作提供了可扩展的示范来源。然而，现有的人到仿真再到机器人（Human2Sim2Robot）流程依赖于预定义程序，难以适应多样化的物体属性和交互，尤其是涉及铰接物体和可变形物体的交互。我们提出 DexAgent，一种智能体式 Human2Sim2Robot 框架，可将单个第一视角人类视频和任务提示转换为具有物理依据的机器人轨迹，用于策略训练。它通过四个阶段运行：人类视频语义理解、基于属性的仿真重建、机器人轨迹优化和机器人数据生成。在每个阶段，DexAgent 通过从工具库中选择合适技能，或在需要时开发新技能，使其方法适应任务和物体属性。属性特定的验证器评估各阶段结果是否满足物理有效性和任务特定要求，并提供反馈以进行改进，从而防止错误在工作流中传播。这种自适应、验证引导的过程使 DexAgent 能够处理多样化的物体和长时程任务。在最后阶段，DexAgent 在仿真中改变物体和机器人状态，以从单个人类视频生成多样化的机器人轨迹，然后对渲染观测进行重新纹理化，以促进仿真到现实的迁移。新开发的技能和验证器会被保留在工具库中，使其能够自演化以积累可复用能力。随着 DexAgent 遇到更多人类视频，这会减少处理时间。在十一个真实世界任务中，使用 DexAgent 生成的数据训练的策略，其成功率达到竞争基线的 3.5 倍。项目网站：https://dexagent123.github.io/。

## Abstract
Human videos offer a scalable source of demonstrations for dexterous robot manipulation. However, existing human-to-simulation-to-robot (Human2Sim2Robot) pipelines rely on predefined procedures that struggle to accommodate diverse object properties and interactions, particularly those involving articulated and deformable objects. We introduce DexAgent, an agentic Human2Sim2Robot framework that converts a single egocentric human video and a task prompt into physically grounded robot trajectories for policy training. It operates through four stages: semantic understanding of human videos, property-based simulation reconstruction, robot trajectory optimization, and robot data generation. At each stage, DexAgent adapts its approach to the task and object properties by selecting suitable skills from its tool library or developing new ones when needed. Property-specific verifiers assess stage outcomes for physical validity and task-specific requirements and provide feedback for refinement, preventing error propagation through the workflow. This adaptive, verification-guided process allows DexAgent to process diverse objects and long-horizon tasks. In the final stage, DexAgent varies object and robot states in simulation to generate diverse robot trajectories from a single human video, then retextures the rendered observations to facilitate sim-to-real transfer. Newly developed skills and verifiers are retained in its tool library, making it self-evolving to accumulate reusable capabilities. This reduces processing time as DexAgent encounters more human videos. Across eleven real-world tasks, policies trained with DexAgent-generated data achieve a 3.5x higher success rate than competing baselines. Project website: https://dexagent123.github.io/.

## 1. 核心问题与研究动机

- **背景**：学习灵巧操作（dexterous manipulation）策略需要海量机器人数据，但真实世界采集成本高、难以规模化，多指机器人手尤甚。
- **可用资源**：人类视频是丰富且可扩展的示范来源，包含多样物体交互。
- **核心瓶颈**：现有人类视频→仿真→机器人（Human2Sim2Robot）流程依赖**预定义的固定流程**（重建、运动生成步骤写死），难以适配：
  - 不同物体属性——刚性、铰接（articulated）、可变形（deformable）物体需要不同的表示与约束；
  - 长时程任务——包含多个子目标，可能需要不同的运动生成策略。
- **整体含义**：DexAgent 提出一个**智能体式（agentic）**框架，用单个第一视角人类视频 + 自然语言任务提示，自适应地生成物理上可行的机器人轨迹与训练数据，从而绕开真实机器人遥操作数据采集的规模化难题。

## 2. 方法论

### 2.1 核心思想
- 四阶段流水线：**语义理解 → 基于属性的仿真重建 → 机器人轨迹优化 → 机器人数据生成**。
- 每个阶段：根据任务与物体属性，从**自演化工具库**中选择已有技能，或现场开发新技能；由**属性特定验证器**评估结果，未通过则反馈迭代，直至全部验证器通过或预算耗尽。
- 仅通过验证的输出才进入下一阶段，**防止错误在流水线中传播**。
- 每阶段受给定预算或 100 个 agent turn 限制；预算耗尽即记为失败，不允许带残缺结果交付。
- Agent 骨干可为任意 VLM，通过 API 切换。

### 2.2 工具库：Skill 与 Verifier
- **Skill**：产出资产、位姿或运动；**Verifier**：基于仿真内交互对 skill 产出做接受/拒绝。
- 二者均为带类型参数的普通 Python 函数；改进时**从原函数 fork 而非覆盖**。
- 设计强调**可复制性与跨样本通用性**，不得过拟合单一样本；资产可缓存以省时（因体积差异为可选）。

### 2.3 阶段一：语义理解
- 输入：单段第一视角 RGB 人类视频 + 自然语言任务提示。
- VLM 先从语言提示推断可能物体，再推断物体应具备的属性，回到视频中抽帧验证属性假设。
- 可调用技能辅助：深度估计、重力方向、人体姿态。
- 任务被分解为**尽可能只含单一动作的子任务**（如 pick-and-place 拆为 3 个子任务）。
- 输出 JSON：①物体及类型（刚性/铰接/可变形/其他）；②每个物体在重建阶段必须体现的属性；③子任务序列（执行手、涉及物体、子目标）。

### 2.4 阶段二：基于属性的仿真重建
- 依物体属性选择/编写验证器：
  - 刚性：轮廓、尺度、质量、静止稳定性；
  - 铰接：关节存在性、轴、行程范围、自锁；
  - 可变形：拓扑。
- 若库中已有该类物体的重建技能则直接调用（传入外观与内部属性参数），否则新写；技能必须是**参数化函数**，适用于一组相似属性物体而非单个物体。
- 新技能构建流程：从无可动关节的可编辑 URDF 出发，对每个属性先定义验证器再编辑 URDF，逐个解决后联合运行所有验证器确保不冲突；随后进行第二轮检查，加入新验证器并**测试泛化性**（参数化函数再生成 3 个变体并须全部通过）。
- 物体放置：优化仿真渲染掩码与人类视频掩码的 **IoU**；相机内外参主要靠深度与手部叠加估计，也可手动设定。

### 2.5 阶段三：轨迹优化
- 对每个子任务定义**任务特定成功条件**（如搬运需到达目标位置，操作铰接物需达到目标关节状态）。
- 选择技能确定目标机器人手位姿：可直接重定向人类姿态、优化手指关节复现人–物接触、或按接触/力闭合/间隙等任务需求生成抓取。
- 位姿用任务特定验证器检验（如搬运位姿做抬升与抖动测试；铰接操作位姿做滑动与旋转测试以覆盖关节可达范围）；失败则反馈改进或换技能。
- 通过后由逆运动学求手臂构型，再生成代码连接关键位姿（可选以示范轨迹作为运动先验）；子任务轨迹合成完整 episode，若早期动作导致后续失败则回溯修正；最后用整段轨迹验证器检查运动限制与物理一致性。

### 2.6 阶段四：数据生成与策略训练
- 在可达工作空间内**随机化初始物体与机器人状态**，并为每个配置适配轨迹；每个增广 episode 都需通过相同的位姿与整段轨迹检查。
- 复用已重建资产与已生成解，降低额外演示的生成成本。
- 视觉处理：用 **VOID** 从原视频抹除演示者双手与被操作物体；将标定相机渲染的仿真机器人与物体合成进清除区域，再用 **Blender** 重新纹理；还可渲染额外视角（如腕部视角）。
- 附录细节：先在桌面有效工作空间采样 **1500 个随机种子**，检查任务可行性（可达性、能否找到有效执行），丢弃失败种子，从通过者中随机选 **500 个**用于策略训练，每个配置渲染第一视角 + 左腕 + 右腕三路观测；不足 500 则继续采样。

## 3. 实验设计

### 3.1 数据集与 Benchmark
- **HOI4D**：人–物交互重建评测（刚性 / 铰接分开报告），指标为 F-5、F-10（两个距离阈值下的 F-score）与 Chamfer 距离（CD）。
- **OakInk**：人→机器人重定向质量评测，指标为成功率（轨迹通过物理检查的比例，判定标准：物体平均位置误差 < 0.1 m 且旋转误差 < 0.5 rad）、E_pos、E_rot。
- **真实世界 11 个灵巧任务**：杯子放置、多杯抓取、电池插入（刚性）；开瓶、抽屉放置、剪纸（铰接）；系绳结（可变形）；绘画与擦拭、移液（工具使用）；礼盒包装、电脑安装（长时程协调）。
- **EgoDex（100 段视频）**：用于评估工具库自演化与耗时下降。
- 仿真器：MuJoCo（部分实验）、Isaac Sim（依任务而定）。

### 3.2 对比方法
- 重建对比：HO、IHOI、HORSE、MCC-HO、G-HOP、FoundationPose、Any6D、Do as I Do。
- 重定向对比：Dex-retargeting、SPIDER（MJWP 与 MJWP-act 两变体）、Do as I Do（Sharpa 手），并含其两个消融（去过渡奖励、仅退火采样）。
- 真实机器人对比：Dex-retargeting、Do as I Do、SPIDER、TopoRetarget、EgoInfinity、V2D、GPT-6 Astra（零样本）。

### 3.3 物理实验设置
- 平台：双臂 **YamBox** 工作站，两只 **Sharpa 手**，第一视角 **RealSense D435**，两个腕部 **Zed Mini** 相机。
- 数据采集：每个任务录制一次完整人类示范，640×480、30 fps。
- 评测两种：
  - **轨迹回放**（open-loop，10 次，至少 1 次成功即算任务成功）——衡量转换出的轨迹是否物理可执行；
  - **学习策略**（闭环，每任务 10 次随机初始物体状态）——用 500 个机器人 episode 微调 **π0.5**。

### 3.4 公平性控制
- 各基线保留其原生支持组件，缺失阶段用**统一实现**补齐；所有方法施加相同的**数据增广与视觉处理协议**，并用同一策略模型训练，以控制变量、比较各方法自身的贡献。
