## 摘要
视觉-语言-动作（VLA）模型、世界-动作模型（WAM）以及离线强化学习方法正在迅速拓展具身策略的设计空间，然而要将这些算法转化为可靠的机器人系统，仍受制于碎片化的数据格式、训练栈、评估协议、推理运行时以及特定于具身形态的接口。我们提出 $\mathrm{FluxVLA}$ Engine，这是一个开放的、配置驱动的平台，可将异构的具身策略组件转化为可复现的从数据到部署的工作流。$\mathrm{FluxVLA}$ 并非引入另一个策略模型，而是为数据集、视觉-语言模型与世界模型、动作头、奖励或优势加权学习、分布式训练、仿真评估、优化推理以及机器人操作器标准化接口。该引擎进一步集成了可组合的双臂仿真、可扩展的自动数据生成，以及与模型解耦的人在回路 rollout、接管、纠正采集和奖励标注。为实现响应式的物理执行，它结合了实时分块（RTC）与加速推理后端、轻量级远程 GPU 服务以及可配置的轨迹后处理。通过这些能力，它将离线学习、仿真验证、在线纠正与真实机器人执行通过共享且可审计的契约连接起来。因此，$\mathrm{FluxVLA}$ 旨在解决那些将有前景的具身学习算法与可复现评估及可靠部署分隔开来的工程瓶颈。代码见 https://github.com/FluxVLA/FluxVLA

## Abstract
Vision-language-action (VLA) models, world-action models (WAMs), and offline reinforcement learning methods are rapidly expanding the design space of embodied policies, yet turning these algorithms into reliable robot systems remains constrained by fragmented data formats, training stacks, evaluation protocols, inference runtimes, and embodiment-specific interfaces. We present $\mathrm{FluxVLA}$ Engine, an open, configuration-driven platform that turns heterogeneous embodied-policy components into a reproducible data-to-deployment workflow. Rather than introducing another policy model, $\mathrm{FluxVLA}$ standardizes interfaces for datasets, visual-language and world models, action heads, reward- or advantage-weighted learning, distributed training, simulation evaluation, optimized inference, and robot operators. The engine further integrates compositional dual-arm simulation, scalable automatic data generation, and model-decoupled human-in-the-loop rollout, takeover, correction collection, and reward annotation. For responsive physical execution, it combines Real-Time Chunking (RTC) with accelerated inference backends, lightweight remote GPU serving, and configurable trajectory post-processing. Together, these capabilities connect offline learning, simulation validation, online correction, and real-robot execution through shared and auditable contracts. $\mathrm{FluxVLA}$ therefore targets the engineering bottlenecks separating promising embodied-learning algorithms from reproducible evaluation and dependable deployment. Code is available at https://github.com/FluxVLA/FluxVLA

## 2. 方法论

### 2.1 核心思想与四大原则
- **统一化（Unification）**：单一实验描述涵盖数据、模型、优化、评估、部署。
- **模块化（Modularity）**：以显式构建与运行时接口隔离实现。
- **可部署性（Deployability）**：保持模型与预处理路径不变，仅替换环境/机器人面向的执行层。
- **可复现性（Reproducibility）**：记录解析后的实验状态，导出评估或部署所需产物。

### 2.2 关键技术机制
- **基于类型键注册表（Registry）的构建**：数据、模型、训练、评估、部署模块通过配置声明、共享构建接口实例化；嵌套模块由其宿主组件组装。注册只建立构建接口，不保证无限可互换——字段名、张量形状、动作维度、时域与生命周期语义仍需一致。
- **分层 Python 配置作为可执行实验规范**：配置指定模型、数据管线、训练策略、评估协议与部署接口，继承复用公共设置；解析后成为组件构建与运行时行为的唯一事实来源。
- **五层模块边界**：数据层（episode → 规范化样本字典）、模型层（字典 → 损失或动作块）、执行层（分布式、优化、检查点、评估循环、运行时状态、轨迹后处理）、服务层（跨进程/机器传输观测与动作）、操作器层（框架状态/动作契约 ↔ 仿真器或机器人 SDK）。
- **训练-评估闭环（eval-after-train）**：训练产出的检查点自动传给同一配置定义的评估器，评估在训练环境释放后作为独立阶段启动。
- **自包含推理产物**：把完整训练模型状态、解析后配置与推理所需元数据打包，评估与部署无需定位原始预训练权重。

### 2.3 数据管线
- 统一为兼容 LeRobot 的 Parquet 表示（低维信号与 episode 索引存 Parquet，相机观测引用 per-episode 视频文件，元数据记录特征 schema、任务、episode、统计量），同时支持 v2.1 与 v3 元数据布局。
- **Episode 感知的时序采样**：从含当前观测、未来动作块与多帧视觉上下文的时序窗口构造样本，采样绝不跨越 episode 边界，用 mask 屏蔽填充项。
- **规范化样本表示**：统一视觉观测、本体状态、语言指令、动作目标、有效性掩码与可选元数据。
- **统计与归一化**：从数据集元数据推导，训练时统计量随模型产物保留并在评估/部署时复用，避免训练与推理动作恢复不一致。
- **多源采样与批处理**：支持单一源、共享统计量的拼接源、保留独立归一化域的成组源；样本在分布式 rank 与 dataloader worker 间确定性分片；balanced 变体定义虚拟 epoch 防止大数据集主导。
- **训练与闭环推理一致性**：仿真/真机从在线观测出发，但收敛到同一模型面向字典，复用同一注册的 prompt/image/state/action 变换。

### 2.4 模型架构
- **可配置模型图**：`BaseVLA` 定义视觉骨干、语言骨干、集成 VLM、模态投影器、动作头槽位；每个槽位由自己的注册表与配置块构建。
- **保留原生结构**：π0 的耦合语言模型+动作专家、WAM 的视频 VAE/文本编码器/多扩散 Transformer 流、Cosmos3 的模态打包等仍由其模型专属 VLA 类持有，但参与同一注册表、检查点、runner 与推理契约。
- **统一训练与预测契约**：`forward(**batch) -> losses` 与 `predict_action(**batch) -> action chunk`。
- **自回归动作生成（OpenVLA 路径）**：连续动作向量经动作 tokenizer 量化后追加到语言目标，训练最小化掩码下一 token 交叉熵
  $$\mathcal{L}_{tok} = -\frac{1}{\sum_k m_k}\sum_k m_k \log p_\theta(z_k \mid o, l, z_{<k})$$
  推理用因果生成路径并将 token ID 转回连续值，同时报告 token 准确率与去 token 化后的 ℓ1 误差。
- **连续流匹配策略（π0 路径）**：对干净动作块 $a$、噪声 $\epsilon$、时间 $t$，插值输入 $x_t=(1-t)a+t\epsilon$，目标速度 $u_t=\epsilon-a$，模型预测 $v_\theta(x_t,t\mid o,l,s)$，训练施加掩码 MSE；推理从噪声出发数值积分学习到的速度场。
- **时序/世界-动作模型**：DreamZero 联合流匹配目标并分别报告视觉动态与动作损失；DiT4DiT 通过显式张量契约强制视频、状态、动作与掩码输入；FastWAM 围绕共享 MoT 构建视频与动作专家；Cosmos3 将文本、视觉隐变量与动作 token 打包进多模态流匹配序列。
- **初始化与适配**：模型构建与预训练权重导入分离，支持 safetensors、张量分片目录、PyTorch 检查点，可配置名称映射翻译外部参数路径；视觉/语言/VLM/投影器可独立冻结；全参数训练与 LoRA 共享数据集与 runner 契约；每个 VLA 提供与 transformer 块对齐的 FSDP 包装策略。

### 2.5 仿真评估
- 评估器从选定检查点与 run-local 产物重建策略与评估设置，复用共享模型与数据契约，基准特定环境语义限制在注册评估器内。目前支持 LIBERO 与 RoboCasa。
- **闭环 rollout**：每 episode 重置环境并构造观测字典，配置的在线数据集施加有序变换管线，策略预测 H 步动作块，评估器执行可配置的 K 步前缀（$1\le K\le H$），每次命令前施加逆归一化，每个转移后检查成功/终止。
- **基准集成差异**：LIBERO 加载套件任务与其初始状态、套件特定时域与 no-op 稳定步、episode 边界清空时序历史；RoboCasa GR-1 使用 29 维动作接口（7 维左臂、6 维左手、7 维右臂、6 维右手、3 维腰部），支持 FluxVLA 原生顺序与官方 GR00T N1.5 顺序，无法识别的约定在构建时失败。
- **分布式与可审计产物**：task-trial episode 作为独立工作单元跨 rank 分片，聚合总/每任务成功计数与时长；保留 rank 日志、结构化摘要、每任务结果与可选 rollout 视频。

### 2.6 真机推理
- **四阶段 runner 契约**：观测预处理 → 动作预测 → 动作后处理 → 轨迹执行；本地与远程推理共用同一契约。
- **同步观测采集**：操作器按时间戳同步传感器消息、维护有界缓冲区、监控可用性/新鲜度/更新率，缺失或陈旧输入在到达策略前显式报告。
- **具身感知动作执行**：操作器验证预测动作块、转换为可执行命令轨迹，经统一接口同步或异步派发；底层安全仍由机器人控制器负责。
- **远程 GPU 推理**：ZeroMQ 请求-回复服务，观测用 MessagePack 或 Protocol Buffers 序列化，RGB 数组可 JPEG 压缩；客户端分别剖析序列化、ZMQ 往返、服务端推理、反序列化与总延迟。因明文 TCP 无内建认证/加密，应限制在可信网络或用 SSH 隧道保护。
- **安全边界**：提供观测同步、维度与模式验证、准备命令、限速发布、轨迹取消与优雅清理；但**不实现碰撞避免、工作空间约束、力矩限制或认证急停控制器**，这些必须由机器人 SDK、底层控制器与部署流程强制。

### 2.7 推理加速
- **推理模型替换**：模型选择在检查点恢复前进行。GR00T 路径保留 `LlavaVLA` 顶层组合但替换为 `EagleInferenceBackbone` 与 `FlowMatchingInferenceHead`；π0.5 用 `PI05FlowMatchingInference` 替换整个视觉-语言与动作生成管线。检查点不变——加速是同一学习参数上的不同执行图。
- **核融合与函数化**：Triton 归一化与矩阵乘算子（部分基于开源 Realtime-VLA 实现），包括融合残差加与归一化、自适应 LayerNorm/RMSNorm、带旋转嵌入的 QKV 投影、带 SiLU 的门控 MLP、带偏置与激活的矩阵乘、原地位置嵌入加；选定热点用自定义 CUDA 扩展（cublasLt GEMM+bias+可选残差、旋转嵌入核）。
- **静态缓冲与 CUDA Graph**：物化权重并为最大配置的图像、prompt、编码器、解码器、动作与去噪维度分配缓冲；首次预测执行算子预热、同步设备、捕获图并存储，后续预测更新输入与噪声缓冲并重放同一图。GR00T 只捕获动作头去噪路径，π0.5 将视觉编码器、语言条件 Transformer 编码器、动作专家与去噪循环手动展开进单一图。
- **数值与配置契约**：融合核、bf16 算术与重排归约会带来与 eager PyTorch 的小差异，后端验证应比较动作空间误差与轨迹/任务行为；静态捕获要求输入不超过分配边界，改变视图数、动作时域、动作宽度、去噪步数或模型结构可能需重新物化与重捕获；首次预热/捕获成本须与稳态延迟分开报告；**模型频率不等于端到端控制频率**。

### 2.8 实时分块（RTC）
- **时序感知调度**防止陈旧命令重放，但不保证连续；RTC 把上一块中时间重叠的动作视为 inpainting 目标，对保证执行的部分固定，对后续重叠部分施加衰减一致性引导。
- **运行时对齐**：设 $t_{ref}$ 为上一块首样本时间原点、$\Delta t$ 为命令周期，则 $\delta = \frac{t_{query}-t_{ref}}{\Delta t}$，runner 从 $\delta$ 线性重采样剩余轨迹并将请求前缀长度 $L$ 钳制到可用后缀。
- **训练时 RTC**：训练阶段模拟延迟条件化——对每个 batch 元素采样模拟延迟 $d$，前 $d$ 个动作位置为已知前缀位置，其每位置扩散/流时间替换为模型干净时间值，重建损失被掩码：
  $$t'_j = \begin{cases} t_{clean}, & j<d \\ t, & j\ge d\end{cases}, \quad \tilde{m}_j = m_j \mathbf{1}\{j\ge d\}$$
  推理阶段前缀条件化：用对齐的上一块动作初始化前 $L$ 个位置，每次去噪更新后恢复它们，并提供干净时间编码。
- **测试时 RTC**：不改训练，仅推理时施加引导。定义位置权重 $w_j$（锁定前缀上为 1，边界后可配置区域衰减至 0），形成前缀误差；原始方法通过去噪器微分误差并施加 VJP 作为速度修正，启用推理梯度并增加计算/内存成本。FluxVLA 另提供低成本直接近似：将加权前缀误差直接加到预测速度上，**这是实现特定的简化，非原论文方法**。
- **与加速推理的交互**：RTC 不得破坏 CUDA Graph 的固定形状假设，加速 GR00T 头在捕获前分配前缀动作、前缀掩码与前缀时间步缓冲；当前两个加速实现只支持前缀条件化机制，VJP 与直接近似仍留在 eager 路径。
